JWT-authorized realtime service

Broadcast messages to the right user, instantly.

Open an authenticated WebSocket connection and share JSON messages with every active connection belonging to the same user.

ws://localhost:4000/?token=<your-jwt>

Quick start

One token, one connection.

Authenticate with the Login API token

Sign a JWT containing a sub claim with the shared JWT_SECRET. Pass it as the token query parameter when opening the connection. Connections with the same subject share a private broadcast room.

Connection

Open a secure user room.

CONNECT/?token=<jwt>Authenticate a socket

JavaScript

The server validates the token and adds the connection to the room identified by sub.

const socket = new WebSocket(
  'wss://your-host.example/?token=' + token
)

socket.addEventListener('message', (event) => {
  console.log(JSON.parse(event.data))
})

Messages

JSON in, JSON out.

SENDclient to serverBroadcast a JSON message

Request

Send any valid JSON value. The sender does not receive its own message.

{
  "type": "note.updated",
  "message": "Hello from the client"
}

Broadcast

Every other open connection with the same JWT sub receives the original JSON unchanged.

{
  "type": "note.updated",
  "message": "Hello from the client"
}
ACKserver to senderReport delivery count

Successful response

The sender receives an acknowledgement after the message is broadcast.

{ "type": "ack", "clients": 2 }

Invalid JSON

Malformed JSON is rejected without closing the connection.

{ "type": "error", "message": "Invalid JSON message" }

Close codes

Authentication failures are explicit.

CodeMeaningWhen it happens
4001ACCESS_TOKEN_MISSINGThe connection has no token query parameter.
4001ACCESS_TOKEN_EXPIREDThe JWT has expired.
4001ACCESS_TOKEN_INVALIDThe JWT is invalid or has no sub claim.
403Origin not allowedThe request origin does not match FRONTEND_ORIGIN.
Keep JWT_SECRET identical between the Login API and this service. Never expose it in browser code or commit real environment credentials.
